# 05｜实施计划（树状生长）

> 本文件是实现的生长计划：一次只长一层，每层可运行、可提交、可推送。
> 设计依据见 [03｜总体架构](03_总体架构.md) 与 [04｜详细方案](04_详细方案.md)。

## 技术基线

- Node.js 26（本机 v26.12.1），ESM。
- 零外部依赖：`node:http`、`node:sqlite`、`node:test`。
- Center 是 HTTP 服务；Client 是命令行，只与 Center 交互，不接入任何编码 CLI。
- 存储：SQLite 文件 `center/data/center.db`（不入库）。
- 端口：`CENTER_PORT`，默认 `8787`。

## 生长层次

| 层 | 内容 | 完成标志 | 状态 |
|---|---|---|---|
| T0 骨架 | 两个 package、目录约定、启动脚本、README/AGENTS | `node center/bin/center.mjs` 能起服务；`node client/bin/sap.mjs --help` 能出帮助 | ✅ |
| T1 存储 | SQLite schema、主干条目、事件表、迁移与重置 | 建库脚本可重复执行；能插入/查询主干条目 | ✅ |
| T2 需求与定级 | 需求提交、评估、决定（接受/改级/追问/拒绝） | 能通过 API 走完 submitted → accepted/rejected/needs_info | ✅ |
| T3 任务与认领 | 拆解任务、原子认领、释放 | 两个客户端同时认领同一任务，只有一个成功 | ✅ |
| T4 提交与评审 | commit 引用、自测、逐条完成条件、确认/打回 | 打回后任务回到可认领，历史不丢 | ✅ |
| T5 主干变更与影响 | 变更记录、影响清单逐项处置 | 空清单不等于无影响；处置状态可见 | ✅ |
| T6 端到端 | 脚本跑通完整链、种子数据、文档回填 | `npm run e2e` 通过 | ✅ |
| T7 归置 | store 拆分为 `db/*`，路由拆分为 `http/routes/*`，`store.mjs` 变门面 | 现有测试不改一行即通过 | ⏳ |
| T8 模型 | provider + 评估/拆解/影响三类建议 + 接口 + CLI + 未配置降级 | 未配置时核心链不受影响 | ⏳ |
| T9 面板 | Center 托管静态面板，7 个页面 | 浏览器可走完提需求到关闭变更 | ⏳ |

后三层设计见 [06｜中心增强设计](06_中心增强设计.md)。

每层的提交信息对应一层，便于回溯“树是怎么长出来的”。

## 运行方式

```powershell
npm test      # 单元测试（center + client）
npm run e2e   # 端到端：完整核心链 + 主干变更
npm run center  # 启动中心服务（默认 8787）
npm run client  # 客户端入口
```

## 对象与 ID 约定

`item_` 主干条目、`req_` 需求、`asm_` 评估、`dec_` 决定、`task_` 任务、`clm_` 认领、`sub_` 提交、`rev_` 评审、`chg_` 主干变更、`imp_` 影响项。
