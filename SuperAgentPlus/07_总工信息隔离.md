# 总工信息隔离：方向层与操作层

> 适用于云端 SuperAgentPlus 与单机 SuperAgentPlusLocal。  
> 核心命题：**项目细节会淹没大方向；总工只处理方向/结构，不读 bug 调试上下文。**  
> 本文修正前几版“总工逐任务看验收包”的表述：常规交付验收下移，总工只接收方向简报。

## 1. 问题：细节如何淹没方向

典型症状：

- 总工开始讨论某个空指针、某次测试为什么挂、某个依赖版本冲突。
- 总工上下文里堆满 diff、日志、复现步骤，真正的目标、风险、取舍被挤到边缘。
- 越到项目后期，总工越像“高级 Debugger”，而不是方向负责人。
- 上下文压缩后，留下的是零散 bug 记忆，丢掉的是“为什么做、不做什么、什么不能变”。
- 多个 worker 把各自细节推给总工，总工成为新的瓶颈和污染汇聚点。

**结论：总工需要的是“决策简报”，不是“项目全量现场”。**

## 2. 三层信息模型

| 层 | 谁看 | 内容 | 默认是否进入总工上下文 |
|---|---|---|---|
| 方向层 | 总工 | 目标、范围、有效决策、结构约束、优先级、风险胃口、里程碑、未决方向问题 | 是 |
| 决策简报层 | 总工 | 一页式问题、选项、影响、成本、风险、可逆性、证据指针、建议 | 是（只此一层） |
| 操作层 | worker/操作者/验收人 | 代码、diff、日志、复现、测试输出、调试过程 | **否** |
| 证据层 | 验收人/审计 | 原始证据、环境、哈希、测试报告 | 默认否；按需拉取 |

**硬规则：操作层与证据层不得默认注入总工会话。** 总工需要时，通过“按需细节包”单独获取，且不合并进主上下文。

## 3. 总工的职责边界

**总工拥有：**

- 项目目标、范围、非目标；优先级与取舍。
- 结构/契约决策：公共 API、数据模型、模块边界、核心依赖、迁移策略。
- 风险胃口与例外：哪些风险可以接受，哪些必须停。
- 里程碑/阶段验收：整体是否继续、转向、缩小或停止。
- 方向级争议裁决：多个方案僵持、跨领域冲突、资源分配。

**总工不拥有：**

- 逐 bug 调试、逐行代码审查、测试日志排查。
- 单个 R1 任务的实现细节验收；这由操作者初审 + 独立验收人完成。
- 代替 worker 写代码、执行命令、改仓库。
- 对每个 diff 签字；签字对象是**方向/结构/里程碑简报**，不是实现现场。

**一句话：总工管“做什么、不做什么、为什么、何时停”，不管“这行代码怎么改”。**

## 4. 信息闸门（Information Gate）

在操作层与总工之间设一个**闸门**，负责把工作事件压缩成方向简报。闸门可以由确定性程序 + 有界模型组成，但不能由 worker 直接向总工推送自由文本。

### 4.1 简报必须回答

| 字段 | 要求 |
|---|---|
| 决策问题 | 一句话：需要总工决定什么？不是“请看看这个 bug” |
| 方向关联 | 属于哪个目标/哪个有效决策；不做会怎样 |
| 选项 | 至少两个，含“不做/延后/缩小” |
| 影响 | 范围、成本、周期、可逆性、受影响领域 |
| 风险 | 最坏后果、已知未知、触发条件 |
| 证据指针 | 路径/commit/测试报告链接；**不贴日志正文** |
| 建议 | 提交者的建议与理由，标明是建议 |
| 截止 | 何时必须决定；超时默认 HOLD |
| 已过滤 | 明确写“已排除操作细节”；列出被排除项类别 |

### 4.2 简报的硬约束

- **长度上限**：一页（约 600–800 字）；超了就是没提炼。
- **不含**：stack trace、完整 diff、逐行代码、调试对话、原始日志、个人聊天。
- **可追溯**：每个结论带证据指针；指针可访问，但正文不展开。
- **不诱导**：不能写“AI 认为必须批准”；建议必须标明是建议。
- **安全**：密钥、token、生产数据、个人信息必须脱敏；只留引用。
- **已知未知**：必须列出“我们还没验证什么”，不能只写有利证据。

### 4.3 闸门不能做什么

- 不能替总工做决定；只能准备简报。
- 不能扩大请求范围；只能按原始请求提炼。
- 不能隐藏不利证据；发现缺证据应退回补证。
- 不能把“总工没回复”当作通过。
- 不能把操作层原文直接转发给总工。

## 5. 按需细节包（Scoped Detail Pack）

总工有时必须看细节，例如判断一个结构方案是否可行。此时用**按需细节包**，而不是把细节灌进主会话。

规则：

1. **目的绑定**：必须写明“为了决定哪个问题才看细节”。
2. **范围绑定**：只包含与该决策相关的文件/日志/证据，不打包整个项目。
3. **时限**：`ttl`（例如本次决策结束即失效）；过期归档，不留在主上下文。
4. **独立上下文**：细节包在单独会话/临时工作区查看；看完只把结论写回方向层，不把原文粘回。
5. **访问记录**：谁在何时因为什么看了哪些细节；可审计。
6. **最小化**：能看摘要就不看全文；能看证据指针就不复制日志。
7. **禁止合并**：不得把细节包内容摘要后自动注入总工长期记忆；只记录“结论 + 依据指针”。

**判断标准：总工的主会话里，应该能回答“方向是什么、前三个风险是什么、哪些决策待定”，而不需要知道任何 bug 的堆栈。**

## 6. 上下文卫生

- **物理隔离**：总工使用独立会话/工作区/存储（云端是独立角色视图；单机是独立 session，`direction/briefs/notes` 与 `work/` 分离）。
- **读模型，不是事件流**：总工读“当前有效决策/目标/风险”的投影，不订阅 worker 的原始事件流。
- **不订阅任务频道**：总工不加入每个 bug 的讨论串；只接收方向级通知。
- **定期重置**：每个阶段/里程碑重新注入方向包（目标、有效决策、约束、风险），归档过期细节。
- **决策账本**：长期记忆只保留“决定了什么、为什么、何时复核”，不保留调试过程。
- **压缩策略**：压缩时优先保留决策与假设，删除操作细节；压缩后做一次“方向一致性”检查。

## 7. 云端的三个门（单机没有）

**这一节只适用于云端。** 单机没有审批、没有 G1/G2/G3；单机的“总工”只写方向 note。

前几版把“操作者初审 → 总工终审”当成两级。加入信息隔离后，云端应分为三层：

| 门 | 谁 | 看什么 | 产出 |
|---|---|---|---|
| G1 操作者初审 | CLI 操作者（人） | 候选、证据、自测、契约 | 可提交 / 退回 |
| G2 独立验收 | 独立验收人/领域验收人（人） | 完整候选、证据、复现、回归 | 任务 ACCEPTED / REWORK |
| G3 方向/结构裁决 | 总工 | **方向简报**（不含操作细节） | 方向决策 / 里程碑接受 / 例外 |

- **R1 常规任务**：G1 + G2；不需要 G3。
- **R2 结构变更**：实施前需要 G3（结构决策）；实施后仍需 G1 + G2；里程碑再 G3。
- **R3 高风险**：G3 + 人类复核 + G1/G2；不可逆动作单独授权。
- **如果项目坚持“总工每单签字”**：可以设 `chief_signoff: per_delivery_brief`，但总工只看**交付简报**（能力级变化、风险、证据指针），不看 diff/日志；G1/G2 仍然独立完成。

**单机对应物：** 没有 G1/G2/G3；worker 自己判断实现细节/方向问题，方向问题写 `brief`，总工写 `note`，用户拍板。单机不把 note 叫“批准”。

## 8. 云端与单机的差异

| 维度 | 云端 SuperAgentPlus | 单机 SuperAgentPlusLocal |
|---|---|---|
| 总工形态 | 人类角色/席位，可多领域总工；G3 是正式裁决 | 一个方向会话，可人 + AI；note 是方向指导，不是审批 |
| 上下文隔离 | 角色权限 + 过滤读模型；总工不订阅任务流 | 独立 session/工作区；`direction/briefs/notes` 与 `work/` 分离 |
| 简报生成 | 控制面/信息闸门服务 | worker 直接写一页 `brief`；总工只读 |
| 细节拉取 | 权限化 detail pack + 审计 | 人工摘录 `detail`（purpose + 时限） |
| 裁决 | G1/G2/G3、联合 G3、正式记录 | **没有审批**；note + 用户决定 |
| 共同底线 | 方向层不读操作层；简报一页；细节按需 | 同左 |

**不同点不只是传输与席位数量：云端有治理与责任，单机没有审批。** 两者只共享“方向/操作分离”。

## 9. 污染测试

每季度/每阶段做一次：

1. **方向问答**：只给总工方向包 + 简报，问“当前目标、三个风险、待定决策”；能答对。
2. **细节诱导**：在简报里夹一段 stack trace，看总工是否被带偏；应指出“这是操作细节，不属于本次决策”。
3. **日志洪泛**：连续注入 20 条 bug 日志；总工应拒绝/转交，而不是逐条分析。
4. **决策漂移**：给一个与有效决策冲突的请求；总工应引用决策账本拒绝或发起替代，而不是就事论事。
5. **细节拉取**：总工申请一次 detail pack；看完只能写结论 + 指针，主上下文不增加原文。
6. **单机审批回流**：单机文档/提示词里出现 approve/reject/G1/G2/G3，说明又把云端模型塞进来了。

## 10. 反模式

- 把 worker 的完整会话记录转发给总工。
- 让总工加入每个 bug 的群聊/线程。
- 用“总工终审”作为每个 diff 的必经门。
- 总工会话里保留全量日志，靠模型自己“忽略无关信息”。
- 把“总工看过”当成“总工对实现细节负责”。
- 用 AI 总工自动批 R2/R3，且不区分 advisory/human_approved。
- 把细节包摘要自动写进总工长期记忆。
