# SuperAgentPlus · AI 项目协作开发系统设计提案

> 设计阶段 v0.3 · 2026-11-17  
> 基于工作区三份原始构想材料，重新梳理定位、机制和架构。**只有设计文档与图示，没有应用实现、代码执行器或部署服务。**

## 核心判断

这个方向不应停留在“一个服务器给很多 AI 派任务”。更值得做的是：

**让项目目标、人的意图、有效决策、工作契约、执行证据和人类责任保持连续，把 AI 产出转化为可判断、可接续、可纳入项目的交付。**

建议产品方向暂称 **“共构 · AI 项目协作工作台”**，架构称 **“项目协作控制平面”**；工程目录和工作代号保留 SuperAgentPlus。名称仍待讨论，也未检查商标或同名产品。

## 本轮按你的澄清修订（v0.3）

- **总工只做方向/结构/里程碑裁决（G3）**，不逐任务看 bug 日志、diff、复现；常规 R1 任务由操作者初审（G1）+ 独立验收人（G2）完成。
- 引入**信息闸门 + 方向简报 + 按需细节包**：总工只读 `direction` + 一页 `brief`；需要细节时走 purpose/TTL 的 detail pack，不把原文回填主上下文。
- 云端与单机共用“方向/操作分离”，但**单机没有审批**：单机只有 `direction/brief/note`；云端才有 G1/G2/G3 与责任链。
- 架构图明确画出**中心服务器 / 人类终端 A / 人类终端 B…N / 受控工程设施**；图中注明**任一接入 CLI 都可发起任务**。
- 总工不是服务器角色，也不是固定管理层：可发起、认领、执行；自己执行时仍走 G1，G2 由另一名验收人做。

## 本次完善的七个重点

1. **服务器承载服务，人类终端承载判断**：中心服务器组织、流转、记录；不替人当经理，也不替总工看 bug。
2. **三层门**：G1 操作者初审 → G2 独立验收 → G3 总工方向/结构/里程碑裁决；总工不是逐任务验收员。
3. **总工信息隔离**：方向层/操作层分离；简报一页；detail pack 有 purpose/TTL；总工上下文不含日志/diff。
4. **从任务分发到工作契约**：每项工作有目的、非目标、验收、证据、权限、预算、版本与停止条件。
5. **清晰度与风险分开**：普通工作免逐单开工审批；结构变更多人讨论批准；笼统意图先诊断。
6. **分布式执行有恢复语义**：原子认领、幂等、租约、隔离令牌、到期/撤销检查、迟到候选与失效屏障。
7. **分开交付阶段**：执行结束、G1、G2、G3、集成发布、目标结果不能混为一谈；追溯不等于自动绩效。

## 与原案保持一致的底线

- 任何项目成员都可提出需求，角色不固定为经理与员工。
- 正式项目变更经过统一规约，执行进度和成果必须可反馈、可追溯。
- AI 生成不免除人类监督责任；G1 操作者初审、G2 独立验收、G3 总工方向裁决都是人类动作；结构级变更还必须多人协同批准。
- 总工不是独立管理层，也不是逐任务验收员：总工可发起、认领、执行；G3 只看方向/结构/里程碑简报，不看 bug 日志。
- 普通推进免开工审批；会议结论而非聊天摘要才可生成受批准的实施任务。
- 驳回是交付质量机制，绩效是可选衍生，不反向主导核心流程。

## 修正的关键误区

Worktree 不是安全沙箱，也不消除语义冲突；MCP/A2A 不是自动获得可靠调度的万能协议；中心化权威不等于一台机器或一个大模型；审计/事件记录不天然不可篡改；提交通过占比不是任务首次通过率；签字不等于证明正确，更不能自动确定全部事故责任。“总工”是方向/结构裁决职责，不是逐任务验收员，也不是让服务器扮演超级经理。

**总工上下文会被细节污染：** 让总工读每个任务的日志/diff，方向就会被淹没；G3 只读方向简报，细节按需、限时、独立查看。

这些修正不是否定原构想，而是让它能从概念走向可讨论、可验证的设计。

- 所有场景数据、对象 ID、命令名和模板批准记录均为设计示例。
