## 2. 本轮修订（v0.3 / v0.4）

根据用户对“总工不能被 bug 上下文污染”的澄清，修正 v0.2 的逐任务终审模型：

- **G1 操作者初审**、**G2 独立验收**、**G3 总工方向/结构/里程碑裁决**分层；常规 R1 任务不需要 G3。
- **信息闸门**把操作现场压成一页方向简报；总工只读 `direction` + `brief`，不读日志/diff/复现。
- **按需细节包**（purpose + TTL）用于必须看细节的决策；独立会话查看，结论写回，不粘原文。
- 云端用角色权限 + 过滤读模型；单机用独立 session + `direction/brief/note`；同一人可兼角色但不可共用上下文。
- **v0.4 纠正**：单机版没有审批。G1/G2/G3、approve/reject、lease/grant 只属于云端；单机只有方向会话/工作会话、一页 brief、方向 note。边界见 [08][boundary]。
- 架构图与流程图同步改为 G1/G2/G3，不再画“总工逐任务终审”。

其中“中高风险由另一名总工做 G3”“联合 G3 的具体通过条件”“是否 `per_delivery_brief`”标注为**建议/待确认**，不冒充用户已定规则。

## 3. 设计内容复核

重点检查并明确了：

- 人人可发起/认领，但 G1、G2、G3、结构批准与发布是不同的人类签署。
- R1 无逐单开工审批，正式交付仍需 G1 + G2；R2 多人讨论与批准不能被任务拆分绕过；G3 只处理方向/结构。
- 原始意图、决策草案、有效决策和正式契约是不同对象。
- 提交必须绑定 G1 初审签署，并在提交时关闭执行权；REWORK 先原子新认领，再整改补证、重新初审。
- G2 不要求已关闭的执行租约仍有效，但要求当前候选、契约/决策、证据、G1 签署与验收授权有效。
- G3 绑定 brief/方向包版本；总工不读操作层原文；需要细节走 detail pack，不合并回主上下文。
- fencing 不能替代租约期限/撤销检查；尚未新认领时，旧最大 token 也不能授权过期写入。
- 决策失效先提交权威屏障，再异步通知；G1/G2/G3/集成与失效的并发由权威顺序解释。
- G2、G3、集成、发布与目标观察分开；非代码成果不伪造测试或部署。
- 审计不天然不可篡改，签名不证明正确，提交占比不等于首次通过率或公平绩效。

治理与协议已经过独立设计复核；交付仍是提案，不代表上述性质已有实现或已被运行测试证明。

## 4. 文档与文件检查

最终机器检查记录：[文档链接、编码与图示身份检查][doc-check]。

检查范围：Markdown 导航/引用的本地目标存在性、已标行号是否在文件范围内、UTF-8 可解码、无替换字符、代码围栏闭合、标题存在、表格列数一致，以及图示 HTML 与 candidate 的存在性和摘要。

机器检查不能判断一条引用是否在语义上证明了某个结论；来源解释与设计一致性仍需人工评审。

## 6. 没有被本次证明的事情

- 任一具体 CLI 支持全部接入、取消、恢复、权限隔离或结构化反馈。
- 原对话里关于 SuperAgent、MCP/A2A 或外部插件的产品能力和性能实验。
- 实际系统在并发、离线、故障恢复、未知外部副作用时符合全部不变量。
- 任意代码执行沙箱、安全签名、人类认证与发布凭据边界已经建立。
- 总工授权、联合 G3 规则在真实组织中的可行性，或团队采用后的效率收益。
- 表单、G1/G2/G3 工作台或画板的可用性已通过用户测试。
- 方向简报/信息闸门在真实项目中是否足以让总工做判断；“总工上下文无污染”目前是设计约束，不是运行测量。

下一步应按 [设计验证路线][roadmap]做真实项目的纸面协作演练，再决定技术选型和是否实现。
