# 从“分发 AI 任务”到“对项目结果负责的协作系统”

> 设计提案 v0.2 · 2026-11-17 · 工作代号：SuperAgentPlus  
> 本文是建议，不是已实现能力，也不是对任何同名第三方产品的官方扩展声明。

## 1. 我对这个方向的判断

原构想中的“经理”只是职责举例，不应被扩展成一个常驻的“超级经理”角色。更准确的核心是：**中心服务器承载组织、流转与记录；CLI 操作者先监督并初审 AI 成果；独立验收人做任务级验收；总工只承担方向/结构/里程碑的最终裁决，而且总工也可以认领任务、亲自执行。**当越来越多实现工作交给 AI，系统要保证“我们为什么做、允许怎么做、实际上做了什么、谁先确认可提交、谁验收、谁定方向”始终连在一起，而不让 bug 细节淹没方向。

AI 让产生代码、分析与候选方案变得便宜，却不会自动解决以下问题：

- 有人做了很多工作，但工作对应的目标早已变化。
- 两个人分别通过了测试，放在一起却不能工作。
- 模型声称完成，监督者没有足够信息判断它是否满足真实需求。
- 架构约定在聊天里改变，其他执行者仍依赖旧约定。
- 审核、澄清与集成成为瓶颈，增加智能体反而增加返工。

因此，系统的优化对象应当是**获得人类认可且能在项目中成立的结果**，而不是智能体数量、任务吞吐量或代码产量。

### 一句话定义

**面向 AI 项目开发的协作系统：中心服务器组织工作并维护权威台账，人类终端通过 CLI 执行和初审，独立验收人做任务验收，总工只对方向/结构/里程碑做单人或联合裁决；操作细节不进入总工上下文。**

### 完整主链

项目目标 → 原始意图 → 澄清与诊断 → 提案与决策 → 工作契约 → 任务协作 → CLI/Agent 执行 → CLI 操作者初审（G1） → 正式提交与可信复验 → 独立验收（G2） → 方向/结构/里程碑裁决（G3，仅在需要时） → 集成/发布 → 结果验证。

其中，普通工作可以在既定规则内直接推进；结构变更必须经过多人讨论和相应审批。会议不是必经的仪式，但**需要会议的问题，只有经确认的结论才有权变成实施任务。**

| 笼统需求先诊断、会议结论再分发（原始材料，未随仓库发布） | **保留并修正分级**：清晰度与变更风险是两条轴 | “不清楚”不是比结构变更更高的风险等级 |
| 驳回有理由，绩效只是可选衍生（原始材料，未随仓库发布） | **保留**：理由关联验收条目，支持申诉、需求变化分类 | 降低返工，而不是制造考核工具 |
| Git Worktree 防止并发冲突（原始材料，未随仓库发布） | **修正**：隔离工作副本；另有契约兼容、集成队列、组合验证 | Worktree 不消除语义冲突，也不是安全沙箱 |
| 中心化保证单一事实来源（原始材料，未随仓库发布） | **修正**：项目范围的权威状态与版本约束，不等于单机或单一大模型；服务器不替人做 G2/G3 | 可有多副本、多个规划 Agent，但状态提交规则唯一 |
| 总工式方向裁决（用户在 2026-11-17 会话中的澄清） | **保留并修正**：CLI 操作者初审 → 正式提交 → G2 独立验收 → 总工只对方向/结构/里程碑做 G3；总工也是人类终端，可执行 | 总工不是逐任务验收员；操作细节不进入总工上下文 |
| 事件溯源、不可篡改、人机占比（原始材料，未随仓库发布） | **修正**：审计设计可检测部分篡改；贡献关系可记录，精确价值占比不可自动推断 | 数据库日志不是区块链；行数与价值不是同一量纲 |
| 一次通过率与客观绩效（原始材料，未随仓库发布） | **修正**：首次通过率按“任务首次提交”统计；返工要区分原因和难度 | 通过次数/提交次数不是任务首次通过率 |
| 原四模块未说明的部分 | **新增**：目标结果、版本化契约、租约与隔离令牌、可信证据、集成发布、异常恢复 | 这些决定系统能否在多人与多工具下稳定成立 |

## 3. 名称与产品定位

建议暂时保留目录和工程代号 **SuperAgentPlus**，不要现在就把产品永久命名为某个“Super Agent”。这个系统并不以一个超级智能体为中心。

| 候选名称 | 表达重点 | 取舍 |
|---|---|---|
| **共构 · AI 项目协作工作台**（建议的产品方向） | 人与 AI 共同构建项目 | 易理解；需后续检查商标、域名与同名产品 |
| ProjectWeave（英文候选） | 将目标、决策、贡献与交付编织成网络 | 能表达连续性；不是承诺已经可用的名称 |
| 项目协作控制平面（建议的架构称谓） | 权威状态、工作规约、路由、质量门禁 | 准确，但面向非技术用户不够直观 |
| 人机协作开发操作系统 | 组织工作与工具的底座 | 可作为愿景，不建议作为第一版产品承诺 |
| 分布式人机协作与治理系统 | 原案的技术与制度范围 | 精确但长，“治理”容易掩盖项目开发价值 |

**我的建议：产品讲“共构”，架构讲“协作控制平面”，工程仍用 SuperAgentPlus。** 名称只辅助理解，不影响核心机制。

## 4. 不是谁的替代品

| 现有类别 | 擅长的事情 | 本系统增加的事情 |
|---|---|---|
| 编码 CLI / IDE Agent | 在一个工作上下文中分析、编辑、测试 | 跨工具、跨成员、跨时间的授权与交付连续性 |
| 多智能体编排器 | 把一个请求交给多个执行单元 | 项目级决策有效性、人类责任、验收与集成 |
| Issue / 项目看板 | 记录需求、任务和状态 | 可执行契约、证据绑定、状态提交约束 |
| Git / CI / PR | 版本、构建、代码审查、合并 | 意图/决策到变更的追溯，业务验收与目标验证 |
| 协作文档 / 会议工具 | 讨论、画图、记录意见 | 让确认后的结论转换成受控任务，并检测失效影响 |

系统应当**接在这些工具之间，而不是重新实现全部工具**。它首先是一层协作语义与控制机制，界面和聊天入口都是这一层的不同窗口。

## 5. 九条不可退让的设计原则

1. **目标优先于执行。** 没有明确问题和验收方式，不派发生产性变更；可以先发受限诊断任务。
2. **人人可参与，任一 CLI 可发起。** 成员和总工都可发起、认领、实现；发起走任一接入的 CLI/入口，由背后的操作者承担初审责任。G1/G2/G3 与发布权限分别记录，不由 CLI 名称隐含决定。
3. **AI 提建议和成果，服务器管流转，人作判断。** 模型与中心服务器都不能冒充操作者初审、G2 验收或总工 G3 方向裁决。
4. **工作有契约，变更有版本。** 开工后的验收标准不能被静默修改；上下文变化会使受影响成果需要重新判断。
5. **执行完成不等于交付认可。** 操作者初审、正式提交、G2 验收、G3 方向裁决、集成发布与目标达成分别记录。
6. **并行不能偷走集成责任。** 每个协作组有整体验收和集成责任人；子任务通过不能自动推出项目结果成立。
7. **总工只看方向，不看操作现场。** 总工只读方向包 + 一页简报；日志/diff/复现默认不进其上下文；需要细节时走 purpose/TTL 的 detail pack。
8. **可追溯不能被偷换为监控。** 记录交付所需的责任与证据，不默认上传私人聊天、完整提示词或个人行为轨迹。
9. **扩展性来自稳定核心，而不是提前建设一切。** 先证明契约—执行—验收闭环有效，再引入复杂协同与联邦。

## 6. 承载边界：服务器承载服务，人类终端承载判断

### 中心服务器承载

- 需求接收与组织、工作契约和决策版本、任务池、认领/租约、进度与上下文协调。
- 正式交付登记、G1 校验、G2 验收编排、G3 方向简报/裁决编排、状态机、通知、审计与责任台账。
- 与仓库、CI、制品库和发布平台的受控对接，以及规划助手/信息闸门提供的澄清、拆分、影响分析和一页方向简报。

中心服务器可以部署为一台服务或多个副本，但它**不承载“总工人格”**：服务验权、记票、编排简报、按规则推进状态，不替人判断方向，也不替人看 bug。

### 人类终端承载

- CLI/IDE/Agent 的实际工作会话，以及背后真实人的监督、检查与责任确认。
- **任一接入的 CLI 会话都可以向服务器发起任务/意图**，不需要先成为“经理”；服务器把发起关联到背后的操作者，由其对内容负责。
- CLI 操作者对自己监督的成果做 G1 初审；认为达到交付条件后，才以人的身份正式提交。
- 独立验收人做 G2：看完整候选/证据，决定任务 ACCEPTED / REWORK。
- 总工只做 G3：看方向包 + 一页简报，决定方向/结构/里程碑；**不读日志/diff/复现**。总工也是人类参与者，可以发起、认领、执行；但自己执行时仍走 G1，G2 由另一名验收人做。

### 工程设施承载

代码仓库、可信 CI、制品库和部署环境承载代码、复验、集成与实际发布。中心服务器协调并记录这些事实，不必把所有执行都塞进中心服务。

一个项目在任一时刻有明确的权威版本和提交入口。普通执行中的提问、文件编辑和未通过初审的本地迭代可留在人类终端；认领、正式提交、G1/G2/G3 签署、集成和发布结果必须回到中心服务器。**G3 的简报与详细证据分离：总工读简报，证据留在操作/证据层。**

## 7. 人的角色会怎样变化

原案强调人负责监督与验收，这是底线。现在至少有三个人类判断动作：CLI 操作者的 G1 初审、独立验收人的 G2 任务验收、总工对方向/结构/里程碑的 G3 裁决。人也并非只能审批，人的高价值工作还包括：

- 判断什么值得做，定义真实用户场景与取舍。
- 发现模型没有理解的约束，允许或拒绝探索。
- 确认架构变化和业务风险，记录可被后续检验的假设。
- 对照证据和演示判断“做对了什么”，而不只看“做完了多少”。
- 处理利益冲突、验收争议、资源优先级和异常发布。

这些职责按任务切换。同一成员在任务 A 可以是 CLI 操作者，在任务 B 是 G2 验收人，在任务 C 是 G3 总工，在任务 D 又亲自实现。总工自己执行时，也要先以操作者身份初审并正式提交；G2 由另一名验收人做；是否允许同一人在同一任务上再做 G3，由项目章程明确。**建议**中高风险成果由另一名总工做 G3，但这不是把总工固定成不干活的管理层。

**总工上下文卫生是硬要求：** 总工只读方向包与方向简报；日志、diff、复现、调试对话默认不进入其会话；需要细节时走 purpose/TTL 的 detail pack，看完只写结论与证据指针。完整机制见 [总工信息隔离](07_总工信息隔离.md)。

## 8. 五个值得畅想、但有边界的扩展

### 8.1 活的项目记忆：不是更大的聊天历史

把有效决策、契约、依赖、验收原因、事故与结果连成“项目记忆图”。新任务只拿相关且有出处的上下文包。旧决策被挑战时，系统能指出哪些任务、证据和发布候选可能失效。

**前提**：团队愿意维护最少的决策与依赖信息。**风险**：依赖图不完整，不能承诺找出所有影响。**验证**：换一个未参与原讨论的人/工具，是否能据此正确接手。

### 8.2 先演练协作，再投入实施

对于结构变更，AI 可生成“协作预演”：哪些模块受影响、哪些契约需变、哪些角色应参与、可能发生什么冲突。人选择方案后再进入实施。

**前提**：有当前架构和可信依赖数据。**风险**：预演不等于证明，模型会漏掉隐性耦合。**验证**：事后比较预测与真实影响，持续暴露盲区，而非宣传自动正确。

### 8.3 可切换职责的动态小队

围绕一个结果临时组合实现者、验证者、领域专家与集成责任人。任务可以主动认领、邀请协作或系统推荐；推荐不能替代授权，也不能以未经校正的个人分数永久封锁机会。

**前提**：能力、权限与可用时间可被适度描述。**风险**：推荐放大历史偏差。**验证**：协作是否减少等待和返工，是否保留成员拒绝与解释机制。

### 8.4 让“停止无效工作”成为一等成果

某次诊断证明需求不应实施，或发现假设失效而阻止一批错误改动，也可以是符合契约的有效交付。系统记录负面结论的依据，而不鼓励“必须产出代码”。

**前提**：诊断契约允许否定结果。**风险**：用空泛分析拖延。**验证**：结论能否改变决策，证据是否可复核。

### 8.5 跨组织协作只交换契约与证明

未来可由不同组织保留各自代码、人员和凭据，只交换经过授权的工作契约、公开接口、证据摘要与验收裁决。共同事实是对外契约，而不是互相读取全部内部会话。

**前提**：清晰的法律、数据和验收边界。**风险**：远程证明不能代替对供应方的信任评估。**验证**：先做单项目受限协作，再谈联邦；第一版不引入区块链或复杂共识。

## 9. 设计阶段的主要假设

| 假设 | 暂用建议 | 如果不成立 |
|---|---|---|
| 首批用户是一个有共同项目与代码仓库的小团队 | 用单项目、少量成员验证，不预设万人网络 | 先收敛共同治理规则，而不是扩容调度 |
| 团队能指定 G1/G2/G3 角色 | 每个正式任务在 READY 前确定操作者、G2 验收人；R2/R3 另定 G3 总工 | 没有验收/方向容量的任务不能无限启动 |
| 代码仓库和 CI 能提供可引用结果 | Git/CI 作为事实提供者，系统不重建 CI | 先完成手工可信证据链与受限复核 |
| 总工可发起、认领与执行 | 总工是方向裁决职责，不脱离一线 | 若组织把总工设为纯管理层，需另设可执行的职责模型 |
| 允许低风险任务直接认领 | 采用既定政策授权，保留 G1 初审 + G2 验收；G3 不介入 | 提高风险层级，明确对自治的限制 |
| 异构工具可由人或适配器提交结构化消息 | 支持不同接入等级，不要求所有工具完全自动化 | 先做半自动桥接，不伪装统一能力 |

## 10. 最需要避免的方向偏移

不要把这个系统变成：

- 一个中央 LLM 不断替所有人“拍脑袋派活”的系统。
- 一个所有事情都必须开会和签字的流程放大器。
- 一个被任务数量、驳回次数和人员排名绑架的考核产品。
- 一个假装所有 CLI 都能自动接入、自动取消和自动恢复的万能协议。
- 一个只在子任务上显示绿色，却无人对最终集成结果负责的看板。

**最重要的判断标准：这套机制是否让团队更少做错事、更容易接续工作、更有能力判断交付，而不仅仅是让更多 Agent 同时跑起来。**
